**This release: upstream llama.cpp v1.0.0.** Same source as the GB10 releases `v0.20261113.0-gb10-cu134` and `v0.20261113.1-gb10-cu135`; the build commit adds only release scripts and notes (the tag format below). Upstream base: merged from ggml-org's `v1.0.0` tag (689 upstream commits not previously on the `tuned-builds` branch). `llama-server-tuned --version` reports `1.0.0-dev`. From this release on the tag leads with the upstream version, `v<upstream-version>-<date>.<seq>-<variant>-<cuda>`; earlier releases keep their `v0.<date>.<seq>` names, and `install.sh` ranks every versioned release above them. NCCL is unchanged from the previous release of this variant (2.32.3). Changes that can affect an existing setup, from upstream's v1.0.0 release notes:

- **Removed:** `--defrag-thold`, `llama_set_warmup` and 35 deprecated `llama.h` functions; `clip.h` (merged into `mtmd`). `llmsrv.sh` and `models.ini` use none of them.
- **Server security defaults:** server tools, MCP servers and the MCP proxy on a non-loopback address now need an API key unless `--allow-unauthenticated-tools` is given; media URLs (`image_url`) that point at local or private addresses are refused unless `--media-allow-private-urls` is given. `llmsrv.sh` enables no tools; a client that sends images by private-network URL needs the second flag.
- **Web UI:** upstream's redesigned UI, built by llama-ui-tuned with dependency overrides `@modelcontextprotocol/sdk` 1.32.1, `dompurify` 3.4.17, `fast-uri` 3.1.8, `katex` 0.18.11, `mermaid` 11.17.2, `zod` 4.6.7 (`zod` 4.4.3 from upstream's lockfile is in GHSA-mrhx-c7xc-m3w5, high). Bundled packages with lower-severity advisories remain: `fast-uri` 3.1.8 and `ajv` (moderate), `@sveltejs/kit`, `bits-ui`, `runed`, `svelte-toolbelt` (low).
- **New:** FP8 KV caches (`-ctk/-ctv f8_e4m3`), host-memory MoE expert cache, `/v1/audio/speech`.

**Ollama compatibility shim:** upstream removed `tools/mtmd/clip.cpp`; the shim's two vision-side hooks moved to the same points in `tools/mtmd/mtmd-model.cpp`. Checked on this build with the shipped `llama-server-tuned` and Ollama's single-file `qwen3-vl:2b` (model blob `sha256:ebabfa59...`, used as both model and mmproj): with the shim, a chat completion describes `tools/mtmd/test-1.jpeg` correctly; with the shim disabled (`OLLAMA_LLAMA_CPP_COMPAT=0`) the same file fails to load.

Tested: the full ctest suite passed on this build, 72/72 (log attached), including upstream's new converter tests (`test-conversion-fp8`, `test-kv-cache-scales`), which run in a test venv with upstream's converter requirements. The tarball was checked as extracted (version, ldd, RUNPATH, toolkit libraries) and installed with `install.sh` into a scratch directory, which served a completion. Full-size model: Qwen3-30B-A3B Q4_K_M (18.6 GB GGUF) fully on GPU (-ngl 99, 16k context), chat completions at ~233 tok/s generation (llama-bench tg128 258 tok/s). Not tested on this release: a native Linux host or an R580 driver.

### CUDA / driver compatibility

- **Built with:** CUDA 13.4.
- **Minimum driver:** R580 (>= 580). CUDA 13.x applications run on any driver from that branch on; see "CUDA minor version compatibility" in NVIDIA's [CUDA toolkit release notes](https://docs.nvidia.com/cuda/cuda-toolkit-release-notes/index.html).
- Features introduced after CUDA 13.0 need newer driver branches. Ones this build uses: none. CUDA 13.4 FP8-to-BF16 conversions (`CUDART_VERSION >= 13040`) are compiled into the cubin and need no newer driver.
- **GPU code:** cubin for sm_89 (224 modules) plus PTX. Runs only on that GPU; the driver loads the cubin directly, so nothing is JIT-compiled at load.
- **Host libraries required:** `libcublas.so.13`, `libcublasLt.so.13`, `libcudart.so.13` from any CUDA 13.x install. `libcuda.so.1` comes with the NVIDIA driver.
